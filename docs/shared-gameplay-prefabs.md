# Shared gameplay prefabs: Giant Forest 2 and Shiganshina

Both saved maps use the same linked assets under **`Assets/Prefabs/SharedGameplay/`**:

| Prefab | Scene object / purpose |
| --- | --- |
| `Player.prefab` | `Player`: movement, ODM, health/combat bridge, Scout visual/gear/FX |
| `MainCamera.prefab` | `Main Camera`: the active camera and its single camera controller |
| `PlayerFollower.prefab` | `PLayerFollower`: existing follower/helper hierarchy |
| `LeftHook.prefab` | `LeftHook`: existing left rope renderer |
| `RightLine.prefab` | `RightLine`: existing right rope renderer |
| `HUD.prefab` | `Canvas`: saved HUD, crosshair, legacy menu and ground-check helper |
| `EventSystem.prefab` | `EventSystem`: existing UI input system |
| `GameManager.prefab` | `GameManager`: music sources and in-game menu controller |
| `MusicSource.prefab` | `TmpMusicElement`: existing standalone music source |
| `TitanSpawner.prefab` | `Titan random spawner`: population, timing, placement and arrival effects/audio |

## Change something in both maps

**Double-click the prefab in the Project window, edit it in Prefab Mode, and save.** Both maps inherit the changes. For example:

- Movement, gravity, jump, ODM or player health settings: **Player**.
- Zoom, FOV, camera offset, speed streak settings: **MainCamera**.
- Titan cap, intervals and lightning volume: **TitanSpawner**.
- Saved HUD layout/crosshair: **HUD**.

Changing a value on an instance in a scene normally creates a **local override**, not a global change. You can selectively apply that particular property to its prefab. Avoid **Apply All** on an entire map instance: its scene bindings, spawn positions and map-specific values are intentionally local.

Runtime Stats/J menus are generated by their existing scripts; changing the archived saved panel does not redesign those generated menus. Wind, footsteps and Titan audio palettes remain the existing shared ScriptableObjects in Resources. The current saved actor prefab `Assets/Prefabs/Titans/ModularTitanPrototype.prefab` and nested Scout/model prefabs continue to be reused; their art/rig assets were not duplicated or rewritten.

## What remains map-specific

Environment, terrain/buildings/trees/walls, lighting, navigation managers, geometry roots, baked navigation data, spawn positions and deliberate per-map differences remain in their original scenes. The retired `ThirdPeronscam` Cinemachine rig stays scene-local and keeps its existing disabled/legacy state. The **active Main Camera** is shared.

The shared defaults come from the current saved Giant Forest scene. Current Shiganshina differences are retained as overrides, notably:

- Player/camera/follower starting positions.
- Titan sizes: town **3/5/6**, forest **3/5/6/4** (including the existing unsupported 4x choice; no sizes or bakes were changed).
- Titan custom spawn bounds.
- **Spawn lightning volume: forest 0.1, town 0.25.** The town's existing `Sound Volume` override takes precedence over the shared prefab. To make later prefab volume edits affect both, right-click **only that Sound Volume field** on the town instance and **Revert** it. This intentionally adopts the shared value; it was not done automatically because it would change user tuning.

Scene-specific references are also deliberate overrides: player↔camera, rope renderers, ground-check helper, HUD/menu, sun and each spawner's own map manager. They remain wired in both scenes. Cross-scene objects cannot be stored in a prefab asset, so these assets are not a zero-configuration complete scene kit when dragged into a brand-new empty map.

## Migration and preservation

`Assets/Editor/SharedGameplayPrefabBuilder.cs` is a guarded, batch-only migration, driven by `tools/build_shared_gameplay_prefabs.py`. It runs only in a closed marker-owned Unity **2021.3.25f1** worker. It neither enters Play nor steps physics or bakes navigation. Publication updates the two **saved scene files** and adds the shared prefab assets; it does not save, stop, switch or reload the user's live Editor session. Original scene metas/GUIDs stay unchanged. Backups of original saved scenes are retained in `Library/SharedGameplayPrefabsOriginalScenes/`.

Existing roots stay roots: there is no new parent above the player and no runtime binder/new movement owner. The migration preserves authored component values, transforms, layer/tag/active state, hierarchy, assets and cross-object bindings. It verifies the loaded scene data before conversion, after conversion and after saving/reopening each worker scene.

Native prefab identity/file IDs naturally change. The audit canonicalizes references by hierarchy/component or asset GUID/local ID. It excludes native screen-space root Canvas-driven layout (which varies with the display/editor window); all authored child UI transforms and Canvas/Scaler settings are checked. Unity may normalize the order of the old FBX's editor-only BoneRenderer; its presence/data and all runtime component ordering are still checked. These are authoring normalization exceptions, not gameplay-test assertion changes.

## Evidence and limits

`ArtSource/SharedGameplayPrefabs/` contains:

- Native migration log and readable summary, including exact per-scene overrides.
- Compressed full owner-digest report: **12,970 forest owners / 9,971 town owners** matched after conversion and reopening.
- **3 existing full-map regression checks passed**: all five forest navigation profiles/routes/walls; 7x/10x native spawns/agents without rebaking; player-only death/respawn preserving actual world actors/navigation/music.
- Preservation hashes, with worker-only company/product identifiers isolating runtime regression PlayerPrefs from the user's game.

No new tests/assertions were added or modified. This is not a full-suite result, a Shiganshina runtime traversal/crowd check, a device/build certification or a fresh auditory/feel review. Previously recorded broad-suite failures remain unresolved.

If Unity has an older copy of a scene open, reload the updated saved scene when appropriate. **Do not discard unsaved user changes** to do so: preserve them and reconcile first. The agent does not force a live reload.
